## Project Overview

Stats site for the San Francisco Softball Meetup group. Built with **Gatsby 1.x** (not modern Gatsby — see gotchas below), AWS Amplify (auth + REST API), antd 3.x, and react-table 6.x.

## Commands

- `npm start` — runs `gatsby develop`; hot-reloading dev server at http://localhost:8000 (GraphiQL at http://localhost:8000/___graphql)
- `npm run build` — production build via `gatsby build`
- `npm run format` — Prettier on `src/**/*.js`
- There is no test suite (`npm test` exits with an error)

## Critical Gotchas

- **`src/aws-exports.js` is gitignored but required.** `src/pages/index.js` imports it to configure Amplify, so the site will not build or run without it. It is generated by the AWS Amplify/awsmobile CLI and must be obtained separately.
- **This is Gatsby v1, not v2+.** Conventions differ from modern Gatsby:
  - `src/layouts/index.js` automatically wraps all pages and renders `children()` as a *function call*
  - `graphql` is a global in page/layout queries (no import)
  - Links use the `gatsby-link` package, not `gatsby`
- **Known startup error**: `RootQueryType.allSitePage field type must be Output Type but got: SitePageConnection` means duplicate `graphql` versions in the dependency tree. Fix: delete `public/`, `node_modules/`, `.cache/`, and the lock files, then reinstall (see README).

## Architecture

- `src/pages/` — files here are auto-routed by Gatsby:
  - `index.js` — landing page, wrapped in Amplify's `withAuthenticator` (sign-in required)
  - `Admin.js` — stat-entry page (route `/admin/`), composed of `AdminSideMenu` (game list) and `AdminStatsTable` (data grid)
- **Backend** is an AWS Amplify REST API named `playerstatsCRUD` with `/playerstats` endpoints, called via `API.get`/`API.post` from `aws-amplify`. `Admin.js` currently renders mock data from `Utils.makeData()` while the API integration is being wired up.
- `src/components/AdminStatsTable.js` — react-table v6 grid where stat cells are `contentEditable` and restricted to numeric input via keyDown/keyUp handlers; edits accumulate in component state and are sent up through an `onSubmit` prop.
- `src/utils/` — `Utils.js` holds the player list, the mock-data generator, and the per-player stat row shape (`gameId`, `o`, `1b`, `2b`, `3b`, `hr`, `rbi`, `r`, `bb`, `k`, `sb`, `cs`, `ab`); `Keys.js` holds keycode constants. Both are re-exported from `src/utils/index.js`.
